# Showcase Screenshots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A scripted showcase that builds a base in 5 stages on each vanilla
planet, and records 30 screenshots and 25 silent clips of it, for the mod
page.

**Architecture:** A throwaway mod in `tools/showcase/` builds and records in
the game. Its placement and camera logic are pure Lua modules with busted
specs. `tools/showcase.sh` runs the Steam copy of Factorio with its own
folders, encodes the frames with `ffmpeg`, and checks the output.
`tools/portal_images.py` uploads a selection to the portal gallery.

**Tech Stack:** Factorio 2.1.24 with Space Age (Steam copy), Lua 5.2 and
busted, POSIX shell, `ffmpeg`, Python 3 and pytest.

**Spec:** `docs/superpowers/specs/2026-11-20-showcase-design.md`

## Global Constraints

- Planets: `nauvis`, `vulcanus`, `fulgora`, `gleba`, `aquilo`.
- Hattorio at its defaults: cell size 41, band width 3. Version 1.1.1 or
  later.
- Stages 1 to 5 per planet. Each stage adds to the stage before.
- Screenshots: 1600 by 900, no GUI, `daytime = 0`. Stages 1 to 5 at zoom 1,
  plus one wide shot at zoom 0.4 after stage 5. Names:
  `<planet>-<stage>.jpg` and `<planet>-wide.jpg`, 30 files.
- Clips: a camera pan of 600 ticks after the screenshots of each stage.
  The script writes one JPEG frame per tick, at 1920 by 1080 and quality
  90. `ffmpeg` encodes the frames to H.264 at 60 frames per second, with
  no audio track. Names: `<planet>-<stage>.mp4` in
  `~/Videos/hattorio-showcase/`, 25 files.
- Every building goes through `surface.can_place_entity` with
  `build_check_type = defines.build_check_type.manual` before
  `create_entity`. The script never forces a placement. Force: `player`.
- No hidden entities, no editor tiles, no infinity chests in view.
- Final JPEGs: quality 85, in `docs/preview/showcase/`. Nothing from
  `tools/showcase/` ships in the mod zip.
- The game: `~/.local/share/Steam/steamapps/common/Factorio/bin/x64/factorio`
  with `SteamAppId=427520 SteamGameId=427520`. Its own config puts
  `write-data` in a scratch folder. `--mod-directory` holds links to
  Hattorio and the showcase mod, and a `mod-list.json` that turns on
  `space-age`, `quality` and `elevated-rails`.
- Prose in British English and the tone of `CLAUDE.md`. Each commit follows
  the workflow in `CLAUDE.md`. Commit messages go to a file first, then
  `git commit -F`.

## Review Focus

- **A layout that fits nowhere.** The spiral search must stop after a
  fixed number of tries and log it, not loop for ever. Task 1 tests a
  layout that fits no position.
- **A belt route that meets a band wider than the underground can span.**
  On a diagonal band the gap can be wider than the basic underground belt.
  The route must try the next tier, then stop and log it. Task 1 tests
  a gap of 5 and a gap of 9.
- **Disk space for the frames.** 600 JPEG frames of 1080p are about 250
  MB. `showcase.sh` must encode and delete each clip's frames before the
  next clip starts. Task 2 checks the frame folder is empty at the end.
- **A planet surface that does not exist yet.** Each surface comes from
  `game.planets[name].create_surface()`. Task 3 checks all five exist
  before stage 1.
- **The game window left open after an error.** `showcase.sh` must close
  the game on every exit path, with a trap. Task 2 tests it with a forced
  error.

### Task 1: Pure placement, routing and camera modules

**Files:**

- Create: `tools/showcase/place.lua`, `tools/showcase/camera.lua`
- Test: `spec/showcase_spec.lua`

**Interfaces:**

- Produces:
  - `Place.spiral(cx, cy, step, count) -> {{x, y}, ...}`: `count`
    positions, the first at the centre, then outward in a square spiral
    with spacing `step`.
  - `Place.fit(layout, origin, can_place) -> bool`. `layout` is a list of
    `{name, x, y, direction}` with offsets from the origin. `can_place(name,
    x, y, direction)` returns a boolean.
  - `Place.find(layout, centre, step, tries, can_place) -> origin or nil`.
    The first spiral position where `fit` is true.
  - `Place.route(start, dir, length, can_place, tiers) -> entities or nil`.
    Lays a straight belt from `start` in `dir` (`"east"` etc.) for
    `length` tiles. Where the next tile is not placeable, it places an
    underground entrance before the gap and an exit after it, with the
    first tier in `tiers` whose reach covers the gap. `tiers` is a list of
    `{name, reach}`, for example
    `{{"underground-belt", 4}, {"fast-underground-belt", 6}}`, with reach
    as the largest gap in tiles.
  - `Camera.pan(from, to, frames) -> {{x, y}, ...}`: `frames` positions,
    eased in and out, first `from`, last `to`.

- [ ] **Step 1: Write the failing specs** in `spec/showcase_spec.lua`.
  A fake grid gives `can_place`: a set of blocked tiles.

```lua
local Place = require("tools.showcase.place")
local Camera = require("tools.showcase.camera")

-- blocked["x,y"] = true for a band tile.
local function grid(blocked)
  return function(_, x, y) return not blocked[x .. "," .. y] end
end

describe("showcase placement", function()
  it("spirals out from the centre", function()
    local p = Place.spiral(0, 0, 4, 9)
    assert.are.same({ 0, 0 }, p[1])
    assert.are.equal(9, #p)
    for i = 2, 9 do assert.is_true(math.abs(p[i][1]) <= 4 and math.abs(p[i][2]) <= 4) end
  end)

  it("fits a layout only where every building can go", function()
    local layout = { { "stone-furnace", 0, 0 }, { "stone-furnace", 2, 0 } }
    assert.is_true(Place.fit(layout, { 0, 0 }, grid({})))
    assert.is_false(Place.fit(layout, { 0, 0 }, grid({ ["2,0"] = true })))
  end)

  it("gives up when a layout fits nowhere", function()
    local layout = { { "stone-furnace", 0, 0 } }
    assert.is_nil(Place.find(layout, { 0, 0 }, 4, 25, function() return false end))
  end)

  it("routes a belt under a band with the cheapest underground", function()
    local band = { ["5,0"] = true, ["6,0"] = true, ["7,0"] = true }
    local route = Place.route({ 0, 0 }, "east", 12, grid(band),
      { { "underground-belt", 4 }, { "fast-underground-belt", 6 } })
    local names = {}
    for _, e in ipairs(route) do names[#names + 1] = e[1] end
    assert.are.equal("underground-belt", names[5])
    assert.are.equal("underground-belt", names[6])
  end)

  it("takes the next tier for a wider gap, and gives up past the last", function()
    local five = {}
    for x = 5, 9 do five[x .. ",0"] = true end
    local tiers = { { "underground-belt", 4 }, { "fast-underground-belt", 6 } }
    local route = Place.route({ 0, 0 }, "east", 14, grid(five), tiers)
    assert.are.equal("fast-underground-belt", route[5][1])
    local nine = {}
    for x = 5, 13 do nine[x .. ",0"] = true end
    assert.is_nil(Place.route({ 0, 0 }, "east", 18, grid(nine), tiers))
  end)
end)

describe("showcase camera", function()
  it("pans from start to end in the given number of frames", function()
    local path = Camera.pan({ 0, 0 }, { 100, 50 }, 600)
    assert.are.equal(600, #path)
    assert.are.same({ 0, 0 }, path[1])
    assert.are.same({ 100, 50 }, path[600])
    assert.is_true(path[2][1] - path[1][1] < path[301][1] - path[300][1])
  end)
end)
```

### Task 2: The showcase mod and runner, for Nauvis

**Files:**

- Create: `tools/showcase/info.json`, `tools/showcase/control.lua`,
  `tools/showcase/layouts/nauvis.lua`, `tools/showcase.sh`
- Change: `tools/README.md` (one section), `docs/design/toolchain-decisions.md`
  (one paragraph)

**Interfaces:**

- Consumes: `Place.find`, `Place.route`, `Camera.pan` from Task 1.
- Produces:
  - A layout file returns `{ [1] = stage, ..., [5] = stage }`. A stage is
    `{ blocks = { layout, ... }, routes = { {from_block, to_block}, ... },
    rails = bool }`. A layout is the list format of Task 1.
  - Log lines that `showcase.sh` reads, each on its own line:
    `SHOWCASE STAGE <planet> <stage> placed=<n> refused=<n>`,
    `SHOWCASE CLIP <planet> <stage> frames=<n>`, `SHOWCASE DONE`,
    `SHOWCASE ERROR <text>`.
  - `tools/showcase.sh [planet ...]`: with no arguments, all five planets.
    Exit 0 only if every check passes.

- [ ] **Step 1: Write `info.json` and `control.lua`**

`control.lua` runs a state machine on `on_tick`. For each planet, and
then for each stage, it does these steps in order:

1. Create the surface (first stage only), and generate the chunks within
   radius 6 of the origin.
2. Place the blocks of the stage with `Place.find`. The centre is the
   centre of the blocks of the stage before, or the origin.
3. Lay the routes of the stage with `Place.route`.
4. Run 300 ticks.
5. Take the stage screenshot `showcase/shots/<planet>-<stage>.png`, at
   1600 by 900 and zoom 1.
6. Wait one tick. Then record 600 frames of `Camera.pan` across the
   bounding box of the base. Each frame is
   `game.take_screenshot{surface, position, resolution = {1920, 1080},
   zoom = 0.75, daytime = 0, show_gui = false, quality = 90, path =
   "showcase/frames/<planet>-<stage>/<frame>.jpg"}`, with the frame number
   padded to 4 digits.

After stage 5, take the wide shot `showcase/shots/<planet>-wide.png` at
zoom 0.4. Burner buildings get 10 coal. Power comes from solar panels and
accumulators in the layouts, or from steam on Nauvis.
